[23][Heading 2] 1.1 Project Background
[24][Normal] Lichess is a free and open-source chess server, and in addition to hosting games it keeps a large public database of chess puzzles. A puzzle consists of a single position taken from a real game in which one side has the possibility of gaining material or delivering checkmate, and each puzzle on the site is given a Glicko rating which indicates the level of strength that a player needs to solve it. The database also records metadata including how many times the puzzle has been played, what tactic
[25][Normal] The rating value cannot be used as an input feature, as it is the target variable. The key question is whether the board structure and puzzle metadata provide enough information to estimate a puzzle's difficulty class without its rating. This is important for training tools that need to estimate difficulty for new puzzles that have not yet been rated.
[26][Normal] I choose this dataset because it is sufficiently large for meaningful evaluation, contains a mix of numerical, categorical, and board-derived features, and the target variable has a natural ordinal structure. The four classes are not equally separable, and the class boundaries are defined on a continuous scale, as discussed in the evaluation chapter.

[29][Normal] The objectives of this project are the following:
[30][List Paragraph] Constructing a full data mining pipeline, starting with a raw CSV file and ending with evaluated models, so that it can run reproducibly on Google Colab.
[31][List Paragraph] It is possible to determine the difficulty class of a chess puzzle—classifying it as Easy, Medium, Hard, or Expert—on the basis of the board features and the puzzle metadata, without making use of the rating value itself.
[32][List Paragraph] Applying descriptive mining in the shape of association rule analysis between tactical themes and difficulty classes can be done using the Apriori algorithm [2].

[35][List Paragraph] To examine the mistakes of the best model and to explain where the remaining accuracy is being lost.

[187][Heading 2] 5.2 The Disadvantages of This Project / Limitations
[188][List Paragraph] Difficulty is a continuous variable that is grouped into bins. The fixed thresholds result in boundary problems which cannot be dealt with correctly without reference to the rating itself, and as a result the accuracy achievable is limited at the level that the best model attained.
[189][List Paragraph] The top three factors are popularity metadata; in the case of new puzzles which have few plays these signals are weak or missing, so the system would have to undergo retraining or have its features adjusted before a genuine cold start deployment could take place.
[190][List Paragraph] The board features are of a structural nature only; the pipeline does not have engine evaluation, tactical depth measures, or solution-line analysis, and this means that the model cannot follow exactly what makes a position difficult.
[191][List Paragraph] The values for the class thresholds (1200 / 1600 / 2000) were determined by design. It is possible that a regression approach which predicts the rating first and then groups the results might yield better performance. It would also be worthwhile to try engine-derived features and models that analyse the move sequence.
